# 可更新通知

Popu 只管理通知内容、展示和更新资格，不推断调用方任务的业务状态。同一次任务持续使用同一个 `request_id`，每次成功更新替换完整 `content`。

## 创建与结束

通知创建时 `updatable` 默认为 `false`，一次性通知不能更新，关闭或超时后归档。需要持续上报的通知显式声明 `updatable: true`。dialog 保留原有的安全内容更新能力，不使用通知专属选项。

更新时省略 `updatable` 表示保持现值。最后一次更新携带 `updatable: false`，原子提交最后内容并关闭更新入口；不提供 `final` 字段，也不允许重新变为 `true`。关闭更新入口不立即关闭窗口：最终摘要仍可完整展示一轮。

```json
{
  "version": "1.0",
  "mode": "notify",
  "template": "notification",
  "updatable": true,
  "duration_ms": 20000,
  "content": {
    "title": "正在备份",
    "blocks": [{ "type": "progress", "value": 0 }]
  }
}
```

更新文件使用 [update.schema.json](../protocol/update.schema.json)，包含 `expected_revision`、完整 `content`，以及可选的 `updatable`、`reshow`、`duration_ms`。RPC 额外携带 `request_id`。更新成功增加 revision；冲突及无效内容不会改变任何状态或时间。

## 收起与再次展示

可更新通知在用户点击 ×、按 Esc 或收到原生关闭事件后进入非终态 `hidden`，记住用户主动关闭意愿。展示超时也进入 `hidden`，但不新增主动关闭记录。

| 情况 | 普通更新 | `reshow: true` |
| --- | --- | --- |
| 正在显示 | 原位更新 | 原位更新，不消耗次数 |
| 自动超时，没有主动关闭记录 | 排队再次展示 | 排队再次展示，不消耗次数 |
| 用户主动关闭过 | 静默保存 | 预算允许时排队再次展示 |
| 主动关闭后的预算耗尽 | 静默保存 | 静默保存，回执 `reshow_suppressed: true` |

默认允许初次展示以外的一次用户关闭后再次展示。次数在原生窗口实际展示后消耗，排队期间的多次更新合并；曾经主动关闭的抑制效果不会被后续自动超时清除。当前次数上限为常量，未来可接入全局设置。

`request.dismiss` / `Client.dismiss` 表示调用方撤销，直接结束通知；它与用户收起窗口不同。

再次展示复用同一窗口与请求 ID，遵循现有 FIFO、最多三条可见及工作区容量规则。历史阅读不会重新展示通知。

## 时长与时间戳

更新省略 `duration_ms` 时不重置当前计时。显示期间提供新时长，从本次成功更新开始重新计时；隐藏期间只保存时长，是否显示仍由上表决定。下一轮展示从实际显示时开始计时。

默认通知模板显示发生时间，例如“15 秒前”，悬停显示绝对时间。创建及成功更新刷新发生时间，包括相同内容的有效上报；隐藏、再次显示、历史阅读和失败更新不刷新。快照以 `occurred_at` 返回时间，历史以 `occurred_at_ms` 返回毫秒时间。

## 最终摘要

```json
{
  "expected_revision": 6,
  "updatable": false,
  "reshow": true,
  "duration_ms": 10000,
  "content": {
    "severity": "success",
    "title": "备份完成",
    "blocks": [{ "type": "paragraph", "text": "2,000 个文件，2.40 GB，校验通过。" }]
  }
}
```

正在显示时原位切换为摘要；自动超时后正常再次显示；用户关闭后仅在明确请求且预算允许时显示。无需展示的最终内容直接归档。终态描述通知展示结果，不代表业务成功或失败。

## 持久化、阅读与清理

可更新记录保存到 SQLite，历史始终展示同一条记录的最新内容，不积累逐次进度日志。关闭时已读的旧进度不会让新结果自动已读。历史阅读带 revision 校验，旧内容迟到的阅读确认不能确认新版本。只有需要阅读、未读且不在展示队列中的记录触发托盘提醒。

Host 重启后恢复更新入口、revision、内容、发生时间、主动关闭记录和已消耗次数，恢复的记录保持收起。重启不自动弹窗，也不重置闲置期限。已关闭更新入口的记录直接归档。

连续 **12 小时未收到成功更新** 的可更新通知自动进入 `stale` 终态：停止展示、关闭更新入口、保留最后内容。它表示“长时间未收到更新”，不推断任务结果。后续更新返回 `notification_expired`。当前时限为常量，未来可接入全局设置。

“清除历史及已收起通知”删除归档及 `hidden` 记录，并关闭被删除记录的更新入口；正在显示、准备或排队的通知保留。清理和更新由协调器串行执行，清理后的更新不能复活记录。普通归档保留最新 500 条；仍活动的通知不受归档条数裁剪。
